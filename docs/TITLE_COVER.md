# 标题与封面（从 AGENTS.md 迁入）

> 从 `AGENTS.md` 迁出：这里放**细节与推导**，结论摘要仍留在 AGENTS.md。

## 标题与封面：顶部不放论文标题，封面放爆款标题

**论文标题不再挂在每一帧顶上**（`_render_slide_layers` 里那块 `<text>` 已删）。
原来是每帧左上角一行 22px 的论文全名，问题很直接：一屏里根本读不完，
而且「每帧都有的东西」等于没有信息量。用户的原话是「顶部的论文标题可以去掉，
设计一个爆款标题」。

**标题现在只出现在封面帧上**，而且是两种字：

| 位置 | 内容 | 来源 |
|---|---|---|
| 封面大字（54px，最多两行）+ 品牌绿短杠 | **爆款标题** | `HOOK_SYSTEM`，模型挑风格写一句 |
| 图注行（18px 灰字） | **论文原题** | `record.title` |

一行抓人、一行交代出处，各司其职。原题仍留着是有意的：只放爆款标题的话，
观众看完不知道这是哪篇论文。

**封面是「论文首页毛玻璃 + 文字标题压在面板上」**（用户的原话是「论文首页毛玻璃展示，
在上面显示文字标题」）。三层叠出来：

1. **底**：论文首页用 `preserveAspectRatio="xMidYMin slice"` **裁满**整张卡
   （留白边就露馅了），对齐到**顶部** —— 那里是论文自己的标题/作者/摘要，留白也多，
   隔着玻璃还看得出「这是一篇论文的开头」；对齐到正中会看到正文那片密集小字。
2. **玻璃**：`feGaussianBlur`（resvg 原生支持，实测梯度从 71 掉到 4）+ 一层冷调薄纱
   （`COVER_GLASS_TINT = #cfdcec`）。用纯白纱会跟白底画布糊在一起、看不出「玻璃」；
   冷调能让玻璃面和面板分层（实测玻璃 236 / 面板 246 / 白底 255）。
3. **面板**：一块 82% 白的圆角面板（`COVER_PANEL_FILL`）+ 一道亮边，
   里面才是爆款标题、品牌绿短杠、论文原题。

**模糊半径就是「毛玻璃的浓度」**，这个数字是量出来的：论文首页的正文小字约 9px 高，
半径 ≥11 时整块底会被糊成均匀浅灰（明暗跨度只剩 14），那已经不是「隔着玻璃看论文」
而是「一张浅灰卡」；半径 6 时字读不出来、但灰度结构还在（跨度 ~22）。所以取 6。

**模糊半径还要跟着「首页在卡里被放大了多少」走**：竖版是把整页缩到 ~0.96 倍，
横版卡片又宽又矮、裁满时首页被放大近 2 倍 —— 同一个半径在横版上明显更清楚（实测
竖版跨度 22 / 横版 34 才对不上）。所以用 `page_scale / COVER_GLASS_BLUR_REF_SCALE` 换算。

**封面排版画在图片卡那一层**（`image_card_markup`），不是骨架层。两个原因：
1. 这一层已经是「会变的那一块」，标题跟着封面一起淡入、一起溶解掉，
   **滤镜图里一处坐标都不用改**（骨架与图片窗口全程不变）；
2. 卡片这一层有两个消费者（分层的编码路径 + 「一页到底」的 `render_slide`），
   抽成同一个 `image_card_markup` 就不会出现「一条路径有标题、另一条没有」
   这种平时看不出来的不一致。

**封面的三条保底规则**（都在 `build_scenes` 末尾，踩过坑才加的）：
- **第一帧一律是论文首页**。社区话术把片头音乐换掉之后，第一句人声从 0 秒开始，
  原来靠片头音乐撑出来的那个独立封面场景（`head_end > 0.3`）就**不存在**了 ——
  于是模型给第一段配的图成了视频的第一帧，爆款标题根本没地方出现。
  所以现在「模型配错了也要把第一帧换回封面」，这也是产品要求
  （观众第一眼得看到这是哪篇论文）。
- **整个片头那几帧都带标题**，不只第一帧：片头话术通常讲两三段、都还停在封面上，
  只放一帧的话标题一秒就没了，观众来不及读。
- **没有封面图就不硬贴标题**（`cover_asset is None` 时 headline 一律为空）。

**爆款标题的写法**（`HOOK_SYSTEM` / `HOOK_SYSTEM_EN`）：不超过 18 个字（英文 8 词），
四档风格（数字结论 / 悬念提问 / 反差 / 代价）**挑最贴的一档**，必须来自论文真实内容、
不许编数字，不要学术腔开头。**提示词写 18、代码上限 `HOOK_MAX_CHARS` 写 20**
（测试钉着「提示词里的数字 == 代码上限」）；超出 20 不到 `HOOK_TAIL_GRACE`(3) 个字一律
整句留着 —— 中文词之间没空格，硬砍必然砍在词中间。

**超长标题的截断和断行都要落在标点上**。截断见 `_trim_hook`（硬砍把 `INT8` 砍成过 `IN`）；
断行见 `design.hook_lines`（**HTML 与 SVG 两套渲染共用**）—— 按宽度折会断出
「…68.7%！Qwen/Kimi」+「同款」这种只剩一个词的末行，而断点明明就在那个「！」上。
截断顺序：① 窗口里靠后的标点（保留 ≥60% 才用）；② 否则**后面第一个**标点；
③ 都没有才硬砍，且不把结尾的英文词砍成两半。英文同理。

**标题是「写一次、以后复用」的数据**：存在 `video.hook`（和 `scenes[i].point` 同一个道理），
`rebuild_video` 通过 `preset_hook` 传回来 —— 重新合成时不该换一句话。
它由 `allow_point_llm` 这个开关统一管（没模型时退回论文原题兜底，见 `_cover_fallback_headline`）。

**封面标题用户能自己改**（`PATCH /api/episodes/{id}/cover`，前端在单集页的视频区）。
理由很直接：这是整条视频最显眼的一行，而模型写的那句话拿不到用户想要的语气和重点。
两个字段、两种作用域：

| 字段 | 作用域 | 说明 |
|---|---|---|
| `headline` | **逐语言一份**（`versions[lang].video.hook`） | 空串 = 清掉自定义、退回显示论文原题 |
| `paper_title` | 整集（`record.title`，跨语言共用） | 省略/空串 = 不动（标题不能是空的） |

- **只写数据、不重新合成**：封面是烘焙进 MP4 的画面，改完要再调 `POST /video/rebuild`。
  分两步是有意的 —— 重新合成要一分钟上下，用户想先把标题改满意再合成一次。
  但**入口必须就地给、而且必须一直在**（被打回过两次）。第一版的按钮只挂在
  「配图过时」的提示条里，而改标题不置 `stale` —— 文案让人去点一个不存在的按钮；
  第二版按 `video.title_pending` 显示，**仍然被打回**：用户点开「点这里改」看到的是
  一个没有合成按钮的面板，只会认为功能不存在。**重新合成是随时可做的动作**
  （换配图、重做画面都算），不该由状态机决定它露不露面 —— 现在它一直在，
  草稿没存时变成「保存并重新合成」（先存再合成，否则拿旧标题白等一分钟）。
- 写进去的值过和模型那条**同一套清理**（`normalize_hook`），所以返回值和传入值可能不同，
  **界面要显示返回值**（前端保存后会用返回的 `video.hook` 回填输入框）。
- **写接口少 `Content-Type: application/json` 就整个不能用**（用户反馈标题改不了）：
  body 以 `text/plain` 发出去，FastAPI 报的错里回显整段 JSON，**看着像双重序列化**。
  `pnpm test:units` 有脚本扫源码盯住这条（详见 `docs/API.md`）。
- **`_HOOK_BREAKS` 里不要放 `/`、`|`**：它们是词中间的分隔符（「Qwen/Kimi 同款」是一个整体）。
- 实测抓到过一个真 bug：`"封面标题：…"` 这种「引号 + 前缀」组合曾整个存进封面 ——
  当时的顺序是「先去前缀、再去引号」，引号挡住了以行首为锚的前缀正则。
  现在**先去外层装饰（引号、星号）再剥前缀**，改这段时注意顺序。
- **「约 N 秒」这类耗时文案会被改动作废**：改渲染管线时顺手量一次（现在 40~95 秒）。



## 页面上的视频封面：`poster` 必须是**视频自己的第一帧**

**踩过的坑（用户直接反馈「http://127.0.0.1:8000/ 没有看到」）**：
封面标题是**画进视频画面**的，而 `<video>` 在没播之前显示的是 `poster` 属性。
前端原来把 `cover_url`（论文首页的原始 PDF 渲染图）当 poster —— **那一页上没有标题**，
于是「封面标题」这个东西在首页首屏、成品展示区、单集播放器上全都看不到，
只有点了播放才出现。用户看到的就是一张裸的论文首页。

**做法**：合成视频时顺手抽一张静帧存下来（`video.capture_poster`，`ffmpeg -ss 1.2 -frames:v 1`，
失败不影响出片），路径存进 `video.poster`，接口给 `video.poster_url`，
`GET /api/episodes/{id}/video/poster`（吃 `?lang=` / `?orientation=`）。
- **抽帧时刻取第 1 段画面的中间**（`min(1.5, max(段时长/2, 0.4))`）：片头有 0.35 秒
  从白底淡入，取 t=0 会拍到一张白纸。
- **静帧按「语言 + 画幅」各一份**：横竖两个画面完全不同，中英两版标题也不同。
- **老数据要补**：`rebuild_video` 不会重抽（它复用编码结果 —— 其实会重编码，
  但为了不整集重跑，维护脚本直接从已有 MP4 抽帧更快，见「补配图」那节的写法）。
  补的时候**路径要按语言取**（`holder.video_path`），不要退回顶层 `video_path` ——
  顶层永远是主语言的，拿它给 en 版抽帧会抽出中文那一版的首帧（第一版脚本就这么错了，
  英文视频配着中文标题）。
- 前端的取法：`video.poster_url ?? cover_url`（老视频没有静帧时退回论文首页 —— 没标题，
  但好过一片空白）。
