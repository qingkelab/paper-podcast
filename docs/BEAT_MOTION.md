# 逐句画面动效：为每一句话生成相应的动效

用户的要求原话：「优化视频，为每句话都生成相应的视频动画」。
追问后确认的是**两者都做**：配图粒度从「段」降到「句」（每句话有自己的画面），
同一句内部再补上跟这句话内容相关的动效。

## 为什么现在做不到

画面是按**段**换的：一段脚本 2~4 句、10~20 秒，配一张图。
所以「一句话讲完了，画面还停在那儿」——字幕在动，画面不动。
（字幕本身早就逐句了：`CaptionBand` 一句一层，按 `beat_windows_aligned` 的窗口淡入。）

## 三条不能破的规矩

1. **不做跟内容无关的动效**。第一版推拉镜头被用户否掉过一次
   （「这种图片无意义的放大、移动和缩小没有价值」），所以这一轮的动效只有两种：
   **这一句换了画面**（因为讲的不是同一件事）和**这一句里的那个数字/子图被点出来**。
2. **长度对齐不能破**。仍然逐段编码成小片段（`-frames:v` 整数帧）→ `-c copy` 拼接 → `-shortest`。
   所有新图层的进入都发生在**片段内部**，帧数一个都不变。
3. **重新合成不许调模型**。逐句配图是「选图」那一步的产物，跟 `scene.image` 一样存下来复用。

## 接口（已冻结，别再改）

```python
@dataclass
class Beat:
    text: str                        # 这一句的字幕文本
    image: str = ""                  # asset id；空 = 沿用本段（= 这一句不切画面）
    focus: dict | None = None        # 这一句的聚光灯框；None = 沿用本段

@dataclass
class Scene:
    ...
    beats: list[Beat] = []           # 空列表 = 整段一张图（老数据天然如此，不需要迁移）

@dataclass
class CaptionBand:
    text: str
    image: Path
    chip: Path | None = None         # 这一句里的数字/关键词**单独一层**（透明底），没有则 None
```

**句数是怎么对齐的**：两边都用 `video.split_caption_beats(text)`（同一套切句规则、纯文本决定），
所以 `Scene.beats[i]` 与编码时的第 i 句一一对应；真实停顿只影响边界时刻
（`beat_windows_aligned`），不影响句数与顺序。**任何一侧改了切句规则，两边都会错位**。

## 编码侧要叠的三层（顺序不能动）

在 `video_encode.encode_video` 的每段滤镜链里，按这个次序插：

1. **逐句图片卡**（骨架之上、聚光灯之下）：第 i 句的卡在 `beat_start_i` 处
   `fade=t=in:st=<beat_start>:d=BEAT_CARD_FADE:alpha=1` 淡入。
   卡是**不透明整卡**，所以「新卡淡入」= 与旧卡的溶解；裁切靠图片窗口那层 `crop`。
   第 0 句不需要单独一层（它就是这一段原本的卡）。
2. **逐句聚光灯**：这一句有自己的框时，淡入那一句的蒙版层。
   只要这一段有任何一句带框，就**不要**再叠段级 focus（会双重压暗）。
3. **逐句数字强调**（`chip`）：在那一句的字幕带之后叠，淡入起点 = 该句起点 + `CHIP_POP_DELAY`。

## 什么时候**不**切画面（守卫，全部要有测试）

- **封面段（`headline` 非空）与片尾品牌段（`brand == "outro"`）永远不切** ——
  封面要始终是「论文首页 + 标题」，「第一帧必须是论文首页」是产品要求。
- **选到的图和上一句相同就不切**（图没变就别动，无意义的溶解只会让人以为卡了一下）。
- **这一句太短不切**（按字数估的时长 < `BEAT_IMAGE_MIN_SEC`）：几个字一闪而过比不切更难看。

## 常量（放 `design.py`，和别的版式令牌在一起）

| 常量 | 值 | 意思 |
|---|---|---|
| `BEAT_CARD_FADE` | 0.25 | 句内换图的溶解时长（参考片的整页溶解是 0.25~0.5 秒） |
| `BEAT_IMAGE_MIN_SEC` | 1.6 | 短于这个时长的句子不切图 |
| `CHIP_POP_SEC` | 0.22 | 数字强调层的淡入时长 |
| `CHIP_POP_DELAY` | 0.12 | 数字强调比这一句的字幕晚一点出现（先读到句子，再看到强调） |

## 落地实况（照实记，别当成「全做完了」）

**做了并验过的**：

1. **逐句换图**：机制通了。真编码两句、两句两张纯色卡 → t=1.4 取到红 `(217,28,28)`、
   t=4.5 取到蓝 `(26,58,217)`；不给 beats 的对照组第二句仍是红。帧数 180/180、时长 6.0/6.0 不变。
2. **句内数字强调**：`chip` 单独一层，在这一句起点 +0.12s 淡入 0.22s。实测该句起点前 0.05s
   胶囊色像素 **75** 个、淡入完成后 **1046** 个（**13.9 倍**）。
   ⚠️ 量的时候容差必须小（3）：那时带子底色 `#f4f7fa` 与胶囊底 `#eef4fb` 只差 3.4 个亮度级 ——
   容差放大到 10，两帧都是 4729，「叠上去看不见」这件事就会**测不出来**（第一次就踩了这个）。
   配套改动：**这一句有 chip 层时，字幕带用 `chip=False` 渲染**（数字照常在同一位置，
   只是没有底色），否则带子里本来就画了胶囊，chip 层再叠一次 = 视觉上什么都没变。
   `render_slide`（一页到底）与 SVG 保底路径**默认仍是 `chip=True`**，观感一点没变。
3. **老路径零退化**：`beats=[]` / 不给新参数的 PNG 与 MP4 哈希与改动前**逐字节相同**。

**没做的**：

- **逐句聚光灯**（`Beat.focus`）。数据侧一直没填（模型只按「段」给 panel），
  所以这一层现在是空的；要做就得先有「这一句讲哪个子图」的来源。
- **真实数据上「换图」很少**：7 次真调用 2 集实测，模型段内换图的意愿只有 **0~2 句 / 约 60 句** ——
  因为脚本的「段」本身就是一个话题，两句往往是一句话的两半。试过三版措辞（保守/鼓励/中性），
  换图数没有变多（0~2），而鼓励版反而把 `generate` 推高（句级 28 vs 15）。
  **也就是说：机制就绪 ≠ 每句话都在换画面。** 想让它更频繁，杠杆在 prompt 或素材池，
  不在编码侧（和聚光灯覆盖率是同构的结论）。

## 怎么验证（必须真编码 + 抽帧，不能只看代码）

1. **逐句换图真的发生了**：造一段两句的场景，两句给两张**纯色**卡（红/蓝），
   编码后抽两个时刻（各句中心）取像素：第一句是红、第二句是蓝。
   顺带断言**总帧数/时长不变**。
2. **守卫真的生效**：封面段给两句不同图 → 全程都是封面（取色两次相同）；
   两句同图 → 只叠一次卡层。
3. **数字强调层**：含数字的句子产出 `chip` 层、不含数字的句子 `chip is None`；
   编码后在这一句起点前后取像素，强调色像素数**变多**。
4. **老数据不退化**：`Scene(beats=[])` 走原来的单卡路径，出片与改动前逐字节同构
   （可用渲染探针对拍 PNG 哈希）。


## 逐句胶囊的两件事：**数字被自己那层底色吃掉**（已修）+ 「弹一下」

### 胶囊里的数字必须画出来

这一层（`caption_chip_page`）的做法是「同一份 DOM/CSS，只把**非数字**的字变透明」，
所以胶囊和字幕带里那颗逐像素重合。原来的 CSS 写的是
`.band-text, .band-text .num { color: transparent }` —— 把数字也一起抹掉了，
于是这层盖上去是一颗**实心的浅蓝药丸**：数字被它自己的底色吃掉。

**怎么发现的**：把两层（带子 `chip=False` + 强调层）**合成一张图**再采像素，
数字位置上没有一个深色像素，那句话读成「这套方法在 ▭ 任务上把精度保住了 ▭。」。
**为什么一直没暴露**：早先的验证量的是「强调色像素变多了」（75 → 1046）——
药丸确实变多了，只是变多的那颗药丸里没有字。

现在的判据是「胶囊里数字的墨迹」（`TestChipSpringActuallyPops::test_the_digit_is_drawn_not_just_the_pill`），
量的是 `#17416f` 的像素数，不是「有没有强调色」。

### 「弹一下」：整层缩放，所以只在一个数字时做

逐帧抓 16 帧（`CHIP_POP_FPS=30`、`CHIP_SPRING_SEC=0.30` + 推迟 0.20 秒），
以那颗胶囊的中心为轴整层缩放 `1 → 1.09 → 1`。

**为什么只在一个数字时做**：缩放只有一个轴心。一句话里两个数字隔了 500px 时，
峰值 1.09 会让远的那颗偏离 45px —— 它的胶囊就对不上带子里的数字了。
一个数字时轴心就是它自己，**对齐误差恒为 0**。多个数字走原来的静态层 + 淡入。
守卫写在两处（Python 少抓 16 帧、页面里再拦一道）。

**为什么不用 ffmpeg 表达式做缩放**：`scale` 的逐帧尺寸变化 + `overlay` 的跟随位移
要写两条互相引用的表达式，而这个仓库里已经有跑通的 Tier B 路径（聚光灯那次），
16 帧 × ~70ms ≈ 1 秒/句，可接受。**滑入那种纯平移**才用表达式（零成本）。


### 两处后续（和「字幕按小句出现」配套）

1. **胶囊底色分出来了**：`design.NUMBER_BG`(#cfe0f8) 与强调行的 `POINT_BG`(#eef4fb) 不再同色。
   字幕带底色 #f4f7fa 和旧胶囊底只差 **3.4 个亮度级**（现在 24.8）—— 旧值下「有个胶囊」
   基本看不见，全靠数字变蓝撑着，这也是「数字被底色吃掉」那个 bug 藏得住的另一个原因。
   SVG 与 HTML 两条路径都改用新令牌（两条路径色不一样是另一类坑）。
2. **点亮时刻跟着小句走**：`CaptionBand.chip_delay`。整句按小句出现之后，
   被强调的数字可能在第 3 个小句里 —— 按固定 0.12 秒弹出来会先出现一颗空胶囊。
   现在由 `_chip_delay_for` 按 `plan_reveals` 的时间表算（数字在第 0 小句时仍是 0.12 秒）。

## 字幕字号：整集一个号（用户：「文字大小要统一」）

**现象**：同一条片子里，相邻两句字幕的大小差一档，读起来像字幕在跳、像被切成几块。

**根因**：字幕是**一句一层**（`caption_band_page`），每层各自跑 `fitText()` ——
短句取到上限 38px，长句为了塞进两行退到 26px。层与层之间没有任何共享状态，
所以「字号统一」这件事**从来没有一个地方负责**。

**改法**：`design.caption_font_size(texts, layout)` 先按同一张近似字宽表把所有句子算一遍，
取「最长那句也放得下」的最大字号（区间 26~38，最多两行），挂在 `Layout.subtitle_font` 上：

- `video.py::_render_scene_layers` 用**全部句子**（与逐句带子同一套 `split_caption_beats`）算一次；
- HTML 路径：`_band_css` 写死这个字号，`_band_body` 把 `data-fit-max`/`data-fit-min`
  设成同一个值 —— `fitText()` 只能选这一个号，**不会再给某一句单独缩小**；
- SVG 路径：`_band_layout` / `_render_slide_layers` 读到锁定的号就不再走 `_fit_subtitle` 的自适应；
- 台账：`video.qa.caption = {font, locked}`（只打在日志里，事后查不到）。

**实测**（库里 6 集真实脚本，按句子算）：字号落在 **30~31px**，每句 1~2 行
（40~56 句里 23~38 句一行、16~25 句两行），没有三行的句子。改前是每句 26~38 不等。

「两句封顶」是早先定过的规矩（用户：「字幕整句 1~2 行」）；这次用户又说「不用这样分段」，
所以 `CAPTION_MAX_LINES=2` —— 超两行的句子让**整集降一档**，而不是让它自己变小。

### 「分段」的真正原因是排版坏了，不是动效

字号统一之后用户仍然贴了一张图：字幕读起来是「这篇论文想解决 | 能不能不重新训练 |
只靠少量物理试验就让机器」，第二行「的就是：| 大模型，| 人恢复状态?」——**字序乱了**。

根因不在字号，在 DOM：小句是 `<span class="clause">`（「按小句依次出现」用的），
而字幕带是 `display:flex`（为了竖向居中）。**span 直接是 flex 容器的子元素，就各自变成
flex item（被 blockify）**，于是一句话被摆成并排的几列、每列自己折行。

修法：正文中间垫一层 `<div class="band-inner">` —— flex 只负责竖向居中，里面照旧是行内文字。
`tests/test_caption_size.py::TestTheSentenceReadsInOrder` 用两条钉着它：
结构断言（小句不能是 flex 容器的直接子元素）+ 真渲染后按行读回来，拼起来必须还是原句
（去掉 `band-inner` 再跑，读回来就是打乱的 —— 这条测过确实会红）。

**这一类坑的教训**：`display:flex` 会把所有直接子元素 blockify。凡是「容器要居中、
内容里又有语义 span」的地方，都要垫一层包裹。

验收入口：`tests/test_caption_size.py`（同一个号、两句封顶、两条路径都认这个号）。


## 图文对应：一张原图不许盖 100 秒（实测根因）

用户报「文本和图像还是无法对应」，先量了三条：

1. **同一张原图连续覆盖多久** —— `e3083750` 41 段里 **f2 连续盖 14 段 / 101 秒**，
   而解说在这 101 秒里走过至少 8 个话题（挑文件 → 节点打分 → 为什么带父目录 →
   相关性分数怎么算 → 数据/代码两类权重 → A3 用语法结构 → 编辑距离 → 三通道优势）；
   f4 接着盖 8 段 / 73 秒。
2. **模型的 `why` 是不是在敷衍** —— 不是：每段的 why 都具体且不同
   （「σ-Reveal 选文件机制」「数据与代码两类权重加权」「命令解析成语法树」），
   说明它认真判了，但判据是「话题属于这篇论文」而不是「这句话讲的东西**图上看得见**」。
3. **逐句选图有没有被我们丢掉** —— 没有：48~73 句里只有 0~1 句带了与段级不同的图，
   所以不是「模型给了逐句、我们按段渲染」。

根因因此是**结构性的**：6 张原图对 31~41 段，模型只能反复挑最像的那张。两条一起改：

- **prompt 把判据写成可执行的**：「这句话讲的机制/数字/步骤在图上画出来了吗？」没画出来就是
  对不上 → 填 `generate`。给了真实反例（讲「相关性分数怎么算」时沿用算法流程图），
  并写明「同一张原图最多连续 3 段」。实测模型开始自己标注「未画出」。
- **确定性兜底**（prompt 改不动的那部分）：`cap_figure_runs` 把超过 3 段的原图区间改判
  `generate`；`split_long_runs` 再把它拆成每 ≤3 段一组 —— 少了这一步，
  `group_generate_runs` 会把剩下的 11 段又合并成**一张**图，问题只是换个形式。

**实测（e3083750 重跑选图 + 重合成）**：最长单图覆盖 **101.1 → 37.7 秒**，
第二长 73.0 → 33.5；`f2` 从 16 段降到 8 段，现场生成图 8 张覆盖 44% 的段落；
音画长度 304.46 / 304.43 秒，帧数 9133 与 `304.43 × 30` 相等。

**顺带记住的取舍**：现场生成图**画的是解说**（所以对得上），但不是论文自己的证据。
prompt 里那条「能对上原图就优先用原图」仍然成立 —— 所以这条兜底的上限**不要调得太紧**
（段数封顶是 3，不是 1）。真要再往前走，靠的是「一张图内部跟着话走」
（聚光灯 / 图解状态），而不是继续加生成图。

## 配图理由：`video.scenes[i].why`

模型在**逐段选图的同一次调用**里顺带写一句「这一段为什么配这张图」，
**只存不渲染** —— 「图像不像文中说的那样」是唯一没法自动判定的错误，有这一列才能复查。
三条规矩（测试 `TestAssignmentNotes`）：**只在采纳了那张图时才收理由**；
**缺失项不延续**（沿用上一段的理由是假信息）；**重新合成时一起复用**。
细节见 `docs/API.md`。

**补配图（图注解析修好之后用）**：`rebuild_video` 复用旧分配，所以新提取到的图
不会自动上画。要跑一次「重新选图」：`build_asset_pool`（+ 上次现场生成的主题图）
→ `build_assign_messages` → `_normalize_per_segment` → 把新 `image` 写回
`video.scenes[i]` → 再 `rebuild_video`。选到 `generate` 的段落**沿用上次那张**，
别现场重画（省一次模型调用 + 几十秒）。音频/脚本/要点/封面标题全都不动。
做过一次：3 集，用到论文原图的段落 0/29、0/51、2/27 → 17/29、19/51、10/27。

**补强调行 / 补子图聚光灯（旧视频用）**：写一个脚本逐集调用 `build_points_messages`
（带上 `panel_options`）→ `_chat_json` → `normalize_point_items`，把 `point` 和
由 `panel` 字母折出来的 `focus` **写回 `video.scenes[i]`**，再调 `rebuild_video` 重新编码
（复用刚写下的文案与框，不会二次调用）。
**已有的 `point` 不要覆盖** —— 跟线上的复用规则一致，只补缺的那些；
`focus` 是这一轮新增的能力，按新结果写。
做过两次：一次 4 集 6 个版本补强调行；一次 4 集 5 个版本补子图聚光灯
（那一次先重新下载原 PDF 重抽图注，脚本里必须有 `if figures:` 保护）。
临时脚本放在 `/tmp`（`backfill_points.py` / `backfill_panels.py`），没进仓库 ——
需要时照上面的三步重写即可。

**怎么测这类改动**：`tests/test_video.py::TestMotionIsActuallyRendered` 会真的编码一段视频、
再抽帧采像素（强调行要滑入即「浅蓝底像素变多」、字幕要在段中间换过、进度条要变长）。
两个踩过的坑：**判据要挑对颜色** —— 用「够亮」去找强调行会把白底也算进去，
得用「偏蓝」；**抽帧要用 `-i` 之后的 `-ss`**（放前面时邻近时间点会取到同一帧）。



## 图内聚光灯：**几何由像素定、语义由模型定**

做法：模型在写「本段要点」的**同一次调用**里再指出「这一段讲的是哪个子图」（一个字母，
如 `"b"`）。字母对应的框由我们自己从图里量出来，据此渲染一张图卡大小的蒙版层
（四条压暗边 + 强调色框线 + 标签），在编码时按 0.25 秒淡入叠在图片卡之上、
强调行/字幕之下。框随 `video.scenes[i].focus` 持久化，重新合成时复用。

**为什么不直接让模型给坐标（第一版的做法，已被否掉）**：模型看不到图（纯文本输入），
它只能猜。两次真实调用量到：

| 集 | 有论文原图的段 | 模型给出的可用框 | 形态 |
|---|---|---|---|
| 666adf5b | 23 / 37 | **8 个** | 面积 0.23~0.72，「左半 / 右半 / 精度表」 |
| 4e594ee2 | 16 / 29 | **4 个** | 全是同一块「左半张」（`x=0,w=0.5,h=1`），只是标签不同 |

第一版更糟：它给的是**整张图**（`w=1,h=1`）外加上一个图名 —— 那等于把整张图压暗一圈，
什么都没突出。所以有了 `FOCUS_MAX_AREA = 0.85`；像素坐标（给 600 这种）也一律丢掉，
因为归一化里无法反推图有多大，猜错会框到角落。
现在 `focus` 只作为**兼容字段**保留（读旧数据里存下来的框），prompt 里已经不再要坐标了。

**现在这条路怎么走通**（三道工序，缺一不可）：

1. **图注要取整段**（`figures._caption_block`）。图注里写着 `(a) … (b) … (c) …`，
   这是「这张图有几个子图」的唯一可靠来源。老实现只取标签那一行的词，
   于是 `(b)` 那半句常常不在库里 —— 实测某集 Figure 10 的图注只有 104 字符、
   6 张图里**一张都读不出子图个数**；改成整段后 Figure 1 的图注从 92 → 560 字符，
   `(a)(b)(c)` 全在。`_caption_block` 用 `page.get_text("blocks")`（段落级切分），
   并要求块**以图注标签开头**，否则退回逐行取法（宁可短，也不要串进正文）。
2. **块数 → 几何切分**（`panels.detect_panels(path, expected=n, marks=…)`）。
   - `expected` 来自图注（`panel_count_from_caption`）；
   - `marks` 是图上 `(a)/(b)/(c)` 标注的**真实文字位置**（`figures._panel_marks`
     逐词匹配、且只认落在图内的单词形式 `(a)`），用来把搜索范围收窄到「两个标注之间那条缝」。
   - **投影只看中间带**（`BAND_INSET = 0.15`）：坐标轴刻度、轴标题、子图标注都排在上下边缘，
     它们让每一列都「有墨」。实测 Figure 2 用整幅投影 0 条沟、只看中间带就有 2 条干净的
     （0.32~0.36、0.62~0.66），正好三块。
   - **切出来的块数必须和 `expected` 完全一致**，否则整张图放弃 —— 字母和块序一旦错位，
     聚光灯就会框错子图。`build_panel_catalog` 盯着这条。
   - 切完还要**收到内容边界**（`_trim_to_ink`）：切出来的框常带一大片白边（Figure 1 左边 18%
     是页边距），框得越松、被压暗的区域越小，突出效果越弱。收过头（<30%）就退回原框。
   - **实测（两篇真实论文）**：Figure 1（图注说 3 块、纯投影切不出来）靠标注切出
     0.182~0.406 / 0.412~0.604 / 0.610~0.818 三块；Figure 2（无图内标注）靠中间带投影
     切出 0.024~0.338 / 0.352~0.633 / 0.648~0.990 三块。两者的字母序都对得上。
3. **模型只做文字活**：给它 `(a) 讲什么；(b) 讲什么`，让它挑字母（`POINTS_SYSTEM` 里
   `panel` 字段）。指错子图比不指更糟 —— 拿不准就写 `null`，我们就不框。

**这一轮的实测结论**（真调用 + 真出片，不是看代码推的）：

| 量的是什么 | 结果 |
|---|---|
| 模型挑子图（4 段脚本：三段各讲一个子图 + 一段总结） | **4/4 全对**（含总结段正确地不框） |
| 老做法「模型给坐标」 | 8/23 与 4/16，且常常是同一块「左半张」 |
| 真实论文切分（Figure 1 / Figure 2） | 各切出 3 块，字母序与图注一致 |
| 真跑一集（43 段） | 12 段有子图清单，模型挑了 **3 段**（其余明确不框） |
| 聚光灯是否真进了 MP4（抽帧对像素） | 框外墨迹亮度 147→228（被压白），框内 147→149（保持清晰） |

覆盖率的取舍：一条 5 分钟的片子里大约 3~4 段有聚光灯（= 有子图清单的段里约 1/4）。
**这是有意的**：模型被明确要求「拿不准就写 null」，因为框错子图比不框更糟。
想让它更激进，改的是 prompt 里那句「拿不准就写 null」——而不是放宽几何那边的守卫。

**顺序问题（踩过）**：收到内容边界之后，同一排的几块 y 会差几个千分点
（实测 0.027 / 0.041 / 0.082），`sort(key=(y, x))` 会把右边那块排到第一。
聚光灯是按序号取块的，顺序错了就框错子图 —— 所以排序是「先按 y 分行（容差 0.12）、
行内再按 x 排」（`_reading_order`）。

**还没做的**：
- **2×2 网格布局**：`(c)` 会回到第一列，按顺序映射会指错块，所以 `_split_by_marks`
  遇到网格排布直接返回空，交给纯几何那条路（能切对就切，切不对就整个放弃）。
- **人工框一次**：像 `POST /figures/{fid}/rotate` 那样让用户在图上拖一个框，
  存进 figure 记录。自动切分对「子图之间夹着下一个子图的纵轴刻度」这类排版仍会失败
  （Figure 1 就属于这类，靠标注才救回来），人工兜底是最后一道保险。
- **旧数据要重抽图注**：库里已有的集，图注是短的那一版，也没有 `panel_marks`，
  所以不会有聚光灯。要重新下载原 PDF 再 `extract_figures` 一遍（批量脚本必须带
  `if figures:` 保护，别把 0 张写回去）。
- 信息图/段落示意图这条线另说：那些图是**我们自己生成的**，几何完全可控，
  所以「逐元素长出来」是可行的（见下）。
