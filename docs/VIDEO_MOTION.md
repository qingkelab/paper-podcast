# 视频动效：只做「讲内容」的动效

这一份是**推导与实测记录**，结论摘要留在 `AGENTS.md`（那里有信噪比预算，放不下这么多）。
改转场、字幕分句、进度条、声波条之前读这里。

## 论文证据与画面类型

逐句配图调用现在也会拿到**已检测且可确认的子图清单**。模型可以为单句选择子图字母，
几何位置仍由 PDF 图像检测得出；只有字母有效、且图注子图数与检测结果一致时才渲染聚焦框。
框只在对应句子的字幕时间窗内显示。缺少可靠映射时展示整张论文图，不做坐标猜测。

图片卡会标明「论文原图 / 论文表格 / 概念示意」（英文视频显示英文标签），帮助观众区分
论文证据和生成的解释图。逐句子图选择与聚焦框会写回 `video.scenes[].beats`，重合成时复用。

`video.qa.visual_plan` 汇总按时长估算的论文图表、生成示意图、子图聚焦、兜底画面和配图理由覆盖，
并列出部分需要人工复核的段落。它是**画面计划的覆盖指标**，不能证明语义匹配或实际可读性；
最终验收仍需抽查成片，尤其是手机尺寸下的图表文字和聚焦框是否准确。

## 一、动效只做「讲内容」的

**被一句反馈否掉过一次，记在这里免得再犯**：
第一版给每段画面加了缓慢推近/拉远 + 平移（Ken Burns），理由是「一张静止画面撑久了像 PPT」。
用户的原话是「**这种图片无意义的放大、移动和缩小没有价值，重点是突出解读的内容**」——
而且否得对：那种运动跟正在讲的内容没有任何关系，观众一眼就看得出它只是在动。

现在留下的三件事，都跟**内容**直接相关：

1. **「本段要点」强调行**（画面上最抢眼的一行）：浅蓝底 + 左侧强调蓝色条 + 大字。
   文案由模型写（`POINTS_SYSTEM`，中文 ≤14 字 / 英文 ≤8 词），**一级来源是上次存下来的**
   （`video.scenes[i].point`，重新合成时复用），模型不可用时退回 `local_point()`。
   **每一段都必须有一句**，过渡段就写「这一段要讲的话题」。
   第一版允许留空，结果整条 250 秒的片子里只有 **18%** 的时间有强调行 ——
   观众的感觉是「这行时有时无」，而不是「这里没什么可强调的」。改成强制后覆盖率 100%，
   视频里实测（每 4 秒采一帧）**82% 的帧有强调行**，缺口全部是片头/片尾那几段（本就不该有）。
2. **字幕逐句出现，并把句子里的阿拉伯数字标成强调色 + 浅色底**。论文解读里
   真正有信息量的往往就是那个「67%」，夹在一行灰字里最容易读漏。这条纯本地，
   不需要任何模型输出，也不会看错。
3. **顶部进度条**：长内容需要「还剩多少」的锚点（不是装饰，是导航）。

**中英文的强调行长度上限必须分开定**：卡成一个数（20 字符）会把英文切得只剩三四个词，
实测出现过「State pool outgrows」「Memory problem is」这种断在半句的行 ——
而 prompt 对英文的要求是 8 个词（≈40 字符）。见 `point_char_limit()`。
收短之后还要**去掉结尾的虚词**（「Quantization error feeds back **and**」→「…feeds back」）。

**英文版的强调 prompt 必须整段英文**（`POINTS_SYSTEM_EN`）。中文 system 里就算写了
「语言与原文一致」，模型给英文脚本写的强调行仍然是**中文** —— 实测踩到过，
英文那一版的画面上整行中文。跟当初解读/脚本 prompt 踩的是同一个坑。

**为什么要点不能靠本地抽取**：实测这几集脚本里只有 **30%~47%** 的段落含阿拉伯数字
（有一集是 0%），而「论文关键词在正文里命中」几乎是 0 —— 脚本是口语化的，不会照抄术语。
所以 `local_point()` 只做最有把握的一件事（把数字拎出来），其余留空、不显示强调行。
挑数字时按信息量排序：**百分比 > 带单位 > 光秃秃的整数** ——
「在 16 个任务上平均成功率 67%」要拎出的是 67%，不是 16。

## 二、转场与语音驱动的动效

参考片子实测（一条 40 秒的论文宣传片 @Chenfeng_X 的 I-DLM 宣传视频，用帧差量出来的画像）：
**40.7 秒、16:9、全程白底（亮度 241~254）、一处硬切都没有**、每 9~10 秒整页换一次、
每次是**约 0.25~0.5 秒的快速淡化**、换画面的同时底部文字一起换、有音轨。
所以这一轮做的是三件事：

1. **画面分层**：`render_chrome()`（骨架：白底 + logo + 图注 + 强调行 + 字幕带）
   + `render_image_card()`（图片卡：图片 + 贴着它的那圈细边框，其余透明）。
   `render_slide()` 保留为两者合成 —— 现有测试和「一页到底」的用法都还走它。
   **边框属于图片卡**（它是贴着图片量的 2px 内缩），所以转场时「带框的图」整体动，
   而不是框留在原地、图在里面换。
2. **转场**（`plan_transitions()`）：默认 `dissolve` 0.35 秒；首段从白底 `fade_in`；
   **同一张图连着讲两段时 `none`**（图没变就别动，无意义的溶解只会让人以为卡了一下）；
   进片尾品牌卡用 `to_card`（上一整页淡出、露出深色卡）；片段太短（压到
   `TRANSITION_MIN_SEC` 以下）就不做。`TRANSITION_STYLE = none|dissolve|push`。
3. **语音驱动**：
   - **字幕换句对齐到真实停顿**（`audio_track.detect_pauses` + `beat_windows_aligned`）。
     先按字数比例算边界，再吸附到最近的停顿中心（容差 0.9 秒、最短句 0.6 秒）。
     实测 250 秒音频 0.14 秒跑完、82 个停顿。**检测失败/没有停顿就退回按字数**。
   - **声波条**：贴在字幕带底部（856×18），跟着**当前说话人**的音量起伏，
     颜色也随说话人（A 麦金 / B 石板蓝）。

**这一轮踩到的坑（都是实测出来的，别再犯）**：

- **转场必须发生在片段内部，不能跨片段 `xfade`**。`xfade` 会重叠、把总长缩短，
  画面就比声音早。做法是新片段内部拿上一段的图片卡当底层：总帧数一个都不变
  （实测 45 帧片段仍是 45 帧），`-frames:v` 的精确控帧和 `-shortest` 的长度对齐全都保住。
- **`showwaves` 在某些宽度下什么都不画**：`s=856x60/856x40/856x18` 输出**全黑**，
  `s=800x18/800x60` 正常。所以固定按 **800 宽**渲染再 `scale` 到目标尺寸（`WAVEFORM_RENDER_SIZE`）。
- **声波条必须画在字幕带之后**。字幕带是一整条不透明的浅底，先画声波条会被整条盖住 ——
  现象是「画面上什么都没有」，而单独跑滤镜链时明明有 793 个墨点。**纯滤镜顺序问题**。
  另外它画的是「黑底彩线」，直接叠上去会留一层黑底：用 `format=gray` 当 alpha、
  和纯色源 `alphamerge` 上色，实测残余暗像素 **0**（而「够亮」这种判据看不出来）。
- **resvg 是按宽度缩放、高度按比例推**，不是拉伸到给定尺寸：传 `width=936` 渲染 896×742 的
  SVG 会得到 936×776。「整页/字幕带/强调行/进度条」都是 936 宽正好蒙对，
  **图片卡是 896 宽，必须显式传 `width/height`**（`_rasterize_custom` 现在支持）。

**验证方式**（这一轮的结论全部来自实测，不是看代码推的）：
逐帧差扫描（`scale=64:36` + 灰度 + rawvideo，在 Python 里逐帧算平均绝对差）——
实测全片最大的单帧变化是 **0.33 秒内 10 帧各 ~20**（就是溶解本身），
**没有任何一帧出现硬切式跳变**；声波条墨迹中位数 346、峰值 2178、残留暗像素 0。

**动效实现上的约束（改的时候别破）**：

- **去掉推拉镜头之后没有把结构退回「concat 幻灯片」**：现在仍然是
  **每段单独编码成小片段**（`-frames:v` 精确控帧数）→ `-c copy` 拼接 → `-shortest` 封音频。
  这么写是因为强调行的滑入、字幕的淡入、进度条的推进都要按帧控制，
  而每段帧数是整数，所以**长度对齐那条保证没有被破坏**（实测 250.77s 对 250.8s 音频）。
- **进度条不能用 `drawbox`**：它的 `w` **只在初始化时求值一次**，
  写 `w='iw*t/duration'` 实测每一帧都是满宽（`t` 取不到值，被钳到 iw）。
  改成「一张全宽色带 + `overlay` 的**逐帧** `x` 表达式从左推进画面」，
  实测 0.2s/1.0s/1.8s 处量到 96/468/842 像素（理论 93/468/842）。
  段与段之间靠**全局起始时间**接续，所以拼起来是一条连续推进的进度条。
- **强调行滑入也用 overlay 的逐帧 `x`**，但曲线已经换成**阻尼弹簧**（见下）。
  这是有意保留的动效：它标记「内容换了一段」，属于第 1 类而不是第 2 类。
- **字幕分句时底图必须不画字幕**（`render_slide(include_subtitle=False)`），
  强调行同理（`include_point=False`）。底图若还留着那行字，第一句/滑入之前就露馅了。
- **每句字幕的时长按字数占比分**（`beat_windows`）：我们只有整段的音频时间轴
  （TTS 是按段合成的），没有逐句时间戳；同一段里语速基本恒定，按字数分是能达到的最好近似。
- **太短的段不拆**（< 28 字）。切成两半每句只剩几个字，闪得更难看。
- **图片区从 812 收到 742**，腾出的 70px 给强调行。图注、强调行、字幕三处位置互不重叠，
  改任何一个都要一起看（`IMAGE_BOX_H` / `CAPTION_TOP` / `POINT_TOP` / `SUBTITLE_TOP`）。
- **CRF 26**：取消推拉镜头后画面重新变成「静止底图 + 局部动画」，压缩率回升，
  同一条 250 秒的片子降到 6~8MB（有推拉镜头时是 16~20MB）。
- **强调行文案属于「可以单独补一次」的数据**：`video.scenes[i].point`。旧视频里没有它，
  所以有 `allow_point_llm` 这个显式开关 + 一个维护脚本（见下面「补强调行」）。
  重新合成时**默认仍然不问模型**（`TestPresetReuse` 钉着这条规则）。


## 弹簧缓动：`缓动曲线` 而不是线性运动

参考做法里那条禁令写得很直白：「用弹簧和缓动曲线，**不要线性运动**」。
按这条清了一遍，有三处要么是**匀速**、要么只有淡入（公式与推导在 `services/motion.py`）：

| 位置 | 改之前 | 改之后 |
|---|---|---|
| 强调行滑入（`POINT_SLIDE_SEC`） | `x='-(W)+W*min(1,t/0.4)'` —— **匀速** 936px | 阻尼弹簧，过冲 2%（≈19px）后落定，**峰值放在 60% 处** |
| 聚光灯从上一处移过来（`FOCUS_MORPH_SEC`） | `cubic-bezier(.3,.7,.3,1)` —— 单调、无过冲（y 都 ≤ 1） | `cubic-bezier(.34,1.28,.5,1)` —— 过冲约 2.5% 后落定 |
| 逐句数字胶囊「弹一下」（`CHIP_SPRING_SEC`） | 只有不透明度淡入 | 以胶囊中心为轴缩放 `1 → 1.09 → 1`（Tier B 逐帧，16 帧） |

**过冲量分开定**，因为屏上距离差两个数量级：滑入 936px，2% 就是 19px（再大就成了「甩过去」）；
胶囊只有 30px 宽，9% 才 2.7px（小到看不出来的话弹簧就白加了）。

**峰值时刻也不是随手取的**（实测调过一次）：

- 强调行：峰值放 30% 处时，0.08 秒就走了 96% —— 等于「啪」一下贴上去，
  而这一行滑入的用意是「标记新的一段开始了」，人得看得见这个过程。放到 60% 处后，
  0.08 秒走 57%、0.24 秒到峰值、0.4 秒落定。
- 胶囊：鼓包（冲激响应）的峰值时刻上限是 `1/k`，所以「0.06 秒弹到位、0.3 秒落定」
  对应的是 `k≈12`（`SPRING_POP_DECAY`），而不是「峰值出现在时长的百分之几」。
  更关键的是**什么时候才开始弹**：胶囊自己也在淡入（跟着字幕带那条淡入走），
  不推迟的话峰值来的那一刻它才 0.44 不透明度，**抓下来的 16 帧里量不到任何过冲**。
  所以鼓包整体推迟 `CHIP_POP_BUMP_DELAY = 0.20` 秒（那时不透明度 0.91）。

**三处用的必须是同一条曲线**：`motion.py` 把公式只写一遍，导出三种形态 ——
Python 求值（测试）、ffmpeg 表达式（`overlay` 的 x/y）、页面 JS（`window.seek`）。
`tests/test_motion.py` 里有一组断言把它们两两比数值，还有一条专治
「过冲设 2% 实际 8.6%」那类参数混用（把自然频率当阻尼频率）。


## 字幕按小句依次出现

**为什么加**：空档的成因很具体 —— 一句 30 字的话念 10 秒，整句在第 0.35 秒就全出现了，
中间那 10 秒画面上什么都不变。实测全片有 59.6% 的时长落在这种「≥4 秒无变化」里
（`docs/VIDEO_QA.md` 有完整数据和标定过程）。既然「句子出现」是这一段里唯一的事件，
那就把它拆开：按小句（`，、；：`）依次显露，读到哪里字长到哪里。

**做法**：每个状态都是一张**整条带子**，同一套排版，只把还没轮到的小句
`color: transparent`（**不是** `display:none` —— 字号自适应是在「文字全在」的前提下
量出来的，藏掉字会让每张带子的字号/换行都不一样，看起来是字在跳）。
时间表由 `video_core.plan_reveals` 算，存进 `CaptionBand.reveals`，
编码时按 `enable='gte(t, beat_start + moment)'` 依次叠上去。
**渲染侧算一次、编码侧直接用** —— 两边各算一遍必然对不上（字幕换句那条老坑）。

规则与实测：

| 参数 | 值 | 为什么 |
|---|---|---|
| 分界符 | `，、；：`（**不含句号**） | 句号是「另一句字幕」的事，由 `split_caption_beats` 管 |
| 最少时长 | 3.0 秒 | 短句一闪而过比不动更难看 |
| 两次间隔 | ≥ 1.1 秒 | 连着闪不如不闪 |
| 末尾留白 | 1.2 秒 | 刚出现就结束等于白搭 |
| 最多状态 | 3 张 | 每多一张就多渲染一次整条带子（Chrome 一页 ~70ms） |

**四个踩过的坑**（都在测试里钉着）：

1. **状态的含义是「从第几个小句起藏起来」**，所以「让第 1 个小句出现」的状态是
   「从第 2 个起藏」。写成「从第 1 个起藏」的话，第一个状态和底图**一模一样** ——
   实测字幕带墨迹一直是 1524，直到第三次显露才变（时间表看起来完全正常）。
2. **最后一个状态必须「全都显示」**。只按小句边界排、再用「末尾要留 1.2 秒」去卡，
   靠近句尾那一刀会被卡掉 —— 那一小句就**永远藏着**，观众最后看到半句话。
3. **状态要铺开，不能贪心取前几个边界**。实测 4 小句 12 秒的句子，贪心取法给
   1.8 / 4.7 / 5.8，后半句又变回一动不动。改成均匀取 + 把「全都显示」放在
   **最后一个小句边界**上（1.8 / 4.7 / 8.4）才对。
4. **强调胶囊要等它自己那个小句出现之后再点亮**（`CaptionBand.chip_delay`）。
   数字落在第 3 个小句时，按老的固定 0.12 秒弹出来，观众先看到的是一颗**空胶囊**
   （框里没字）。另外第 0 张小句在第 0 张带子里就是可见的，算延迟时要把这张「时刻 0」的
   状态一起算进去 —— 漏掉它，数字明明在第一小句里却要等 4 秒才点亮。

**这套只在 HTML 路径生效**：SVG 降级路径的排版是自己按 `_char_width` 表逐行画的，
再实现一遍小句映射等于把同一件事写两遍；降级时退回「整句一起出现」（少一件事，
不会画错）。所以 `plan_reveals` 只在有 Chrome 会话时才调用。

**另一处一起改的**：数字胶囊的底色从 `POINT_BG`(#eef4fb) 分出来，用 `NUMBER_BG`(#cfe0f8)。
理由很直接：字幕带底色 (#f4f7fa) 与旧胶囊底只差 **3.4 个亮度级** —— 一屏里根本看不出
那里有个底，「数字被点出来」全靠数字变蓝撑着。现在差 **24.8**。强调行那条 856px 的宽底
仍然用浅色（大色块深了会像色卡），所以这两个令牌是分开的。


## 入场一律「淡入 + 上升」（借鉴 claude-remotion-skill）

参考做法里写死一条：**绝不用单一的淡入**。我们此前所有「后续状态」都是纯 alpha 淡入 ——
看起来像「图层被打开」，不像「东西被放到位」。

现在两处改成淡入 + 上升，共用同一组令牌（`design.ENTRANCE_*`）：

| 位置 | 之前 | 之后 |
|---|---|---|
| 字幕按小句显露（`CaptionBand.reveals`） | 0.18 秒纯淡入 | 淡入 + **12px 上升**（弹簧，到位轻微回弹 5%） |
| 动态图解镜头的后续状态（`diagram_states`） | 0.3 秒纯淡入 | 同上 |
| 强调行滑入 | 弹簧横向滑入（936px，过冲 2%） | 不变 |

**上升用弹簧表达式，零渲染成本**：`motion.ffmpeg_ease(..., variable="(t-3.500)")` ——
ffmpeg 表达式里没有「相对某时刻」的概念，把时间变量整体替进去就行
（`overlay` 的 `y` 写成 `subtitle_top + 12*(1-p(t-at))`）。

实测（真出片抽帧量字幕带顶边）：带子出现后 0.06 秒时顶边比落定后**低 9~12px**，
0.6 秒时回到原位。`ENTRANCE_RISE_PX` 取 12 是因为那正好是一行字的高度量级，
再大就成了「飞进来」。


## 缓动与弹簧只许具名，不许内联

借鉴之处同上（参考做法的 `theme.ts` 第一行注释：**NEVER inline colors/easings in components**）。
理由不是洁癖：同一个缓动值散落在五个文件里，改一处等于没改，而「这条动画怎么突然不顺了」
是最难查的一类问题 —— 数值本身都是量出来的，必须只有一份。

| 在哪定义 | 里面有什么 |
|---|---|
| `design.py` | `EASE_FOCUS_MORPH`（聚光灯位移的曲线）等 CSS 侧具名缓动 |
| `motion.py` | `SPRING_PRESETS` = `{slide, pop, entrance}` + `spring_kwargs(name)` |

调用点只写名字：`spring_ease(POINT_SLIDE_SEC, **spring_kwargs("slide"))`。
过冲量**按用途分开定**（滑入 2% / 胶囊 9% / 入场 5%）——屏上距离差两个数量级
（936px vs 30px），同一个百分比在小元素上看不出来、在大位移上又成了「甩过去」。

`tests/test_render_discipline.py::TestNoInlineEasing` 三条扫源码盯住：
渲染模块里不许出现 `cubic-bezier(...)` 字面量、不许手写 `exp(-k*t)` 弹簧表达式
（它**看起来**像弹簧，但过冲与峰值时刻和别处对不上）、具名预设必须齐全且拼错名字当场报错。

## 影片语法：从 HyperFrames 学到的（`seam-craft` / `motion-doctrine`）

下面这份是**推导与出处**，结论要落到我们的代码里时，看 `services/seam_audit.py` 与
`docs/VIDEO_QA.md`「接缝审计」一节。

[HyperFrames](https://github.com/heygen-com/hyperframes)（Apache-2.0，6.5 万星）
和我们**是同一条技术路线**：HTML + 无头 Chrome 逐帧 seek + ffmpeg，同样把「确定性」
当产品承诺（same input → same frames → same output）。差别在取舍：
他们**一帧截一次图**（浏览器自己合成全部图层，没有滤镜图要维护），
我们只截「图层变化的那一刻」再交给 ffmpeg overlay —— 我们单机快 ~20 倍，
代价是**图层坐标类**的 bug 得靠我们自己兜（图注压图、图解叠错段都是这一类）。

### 1. Seam Law：切点两侧的动必须对上（我们最缺的一条）

> **How Scene A exits determines how Scene B enters.**
> ① **轴**：x 还是 x、y 还是 y、Z 还是 Z，跨切不许换轴；
> ② **方向**：不许镜像（Z 上方向 = 缩放的**符号**）；
> ③ **速度**：进入初速 ≈ 退出末速（退出 `power4.in` + 进入 `power4.out`，同距离同时长）；
> ④ **相位**：切点必须落在**两边都还在动**的时候 —— 停下来再切、或从静止开始，都是死拍子。

还有三条配套的：

- **The Current（水流）**：整片只选一个主方向，其他方向是**储备**（向上=升华、Z 推近=深入、
  Z 拉远=落地、爆开=离开一个世界）。**不许连续两个接缝反向**，变向必须有可见的因。
- **Carriers（载体）**：眼睛跟物体不跟抽象。最强的接缝是把同一个具体物件交过切点
  （位置 + 速度都接上）。**「Never a crossfade — it has no carrier at all.」**
- **Causal Motion**：因果链上的动效要**同帧点火**（效果从触发它的那一帧开始，
  不许「稍后一点」）；反应幅度跟着质量走（大元素回弹慢）。

**对照我们**：全片默认 `TRANSITION_STYLE = "dissolve"`，而叠化在他们的 anti-pattern
表里排第一。我们当时的判断是「稳」，方向没错（少即是多），但**「稳」的下一步不是更少，
而是一致**：真要做，是给切点选一个主方向和一种过渡并重复使用，而不是继续用叠化。

### 2. Performance：场景要一直在演（判据比我们的严）

- **No idle wobble**：呼吸/漂浮/脉冲这类循环一律禁（读起来像视频在等）。
  进入之后还有好几秒空着 = **编排 bug，该加故事，不是加抖动**。
  —— 这和我们「Ken Burns 被否掉」是同一个结论，但他们把它写成了法律。
- **五种持续动线**（都要在计划里具名）：staged reveals（内容留到解说节拍上兑现）/
  camera with intent（建立→行进→落到主体）/ sequenced UI life（进度、计数、高亮按时间走）/
  animated sequences（卡片归位、元素被拖）/ cursor-led action。
- **判据**：任意一秒暂停，必须有东西正在**有意义地**飞。
  —— 我们只有 `video_qa` 的「4 秒无变化」（下限），没有这一条（质量）。
- **Stillness before climax**：大动作与结果之间留 **0.3~0.75 秒**。
- 时长意图：单元素入场 ≤800ms；退场 ≈ 入场 75%；总错峰 ≤500ms；
  禁 `bounce/elastic` out（准入 `back.out(1.4~1.7)`）；同类元素**共用一个缓动意图**。

### 3. Captions：字幕不是「保留带」（直接打在我们的版式上）

> Center the composition on the **true vertical center (y = H/2)**. Do not shift content up
> to "make room" for captions; a composition centered at 0.42 × H with a **dead lower band**
> is the bug, not the fix. Captions are an **overlay**, not a reserved zone.
> 唯一软规矩：别把关键小字停在底部那 80px 中线带里。

我们的竖版恰恰是那条死带：底部 968→1210（242px ≈ 画布 20%）保留给字幕带的浅底区。
这解释了上一轮量「宽图留白 40~56%」的另一半 —— 我当时只归因于画幅比例，
其实还压着一条 20% 的保留带。

他们的字幕模型分三档，值得记：**drop**（口水词不显示，我们是生成稿，不适用）/
**rail**（默认的干净下三分一字幕 + **行内强调**——我们的数字胶囊就是这个 ✓ 做对了）/
**embed**（**被提升的峰值**：一个大词合成在主体后面，**每个节拍最多一个、不许相邻同现、
间隔至少一个节拍**；「把整段都 embed 掉是常见的错」）。
我们的「本段要点」是每段固定一行（配额式），他们是稀缺且挣来的峰值（稀缺式）。

### 4. 工程纪律（他们的闸门清单）

- **接缝闸门**（`seam-gate.mjs`）逐条数值强制：ledger 一致性、退出时还在动、进入不是从静止、
  实测方向=计划方向、速度匹配（WARN）、**零重叠**（每帧只有一侧可见 = 这不是叠化）、
  Z 符号一致、carrier 矩形连续；还诚实列出**脚本查不了的三条**：改头尾 1 秒就作废那次审计、
  **音频是时钟**（按 VO 的真实词时间轴重排，绝不为了塞进槽位赶读稿）、clip-gating 的坑。
  —— 第 2 条正是我们花一整轮才得出的「字幕要吸到真实停顿」（96%），外部验证。
- **舞台必须不透明**：叠化窗口里两侧不透明度之和 < 1，**底下的东西会透出来**；
  `#root` 没刷底时渲染器把这个凹陷合到默认**白色**页面上 → **每个接缝闪一下白**
  （他们在两条片子上观察到才修）。做法一句话：装配器负责 `#root { background: … }`。
- **覆盖率闸门**（`videoFrameCoverage.ts`）：逐 clip 算 `capturedFrames / expectedFrames`，
  默认阈值 **0.95**，不达标**在编码之前**抛类型化错误中止 —— 宁可不出片，
  也不给一个「看着正常、像素掉了」的 MP4。文件头写着两次线上事故的现场
  （时间戳、平台、CLI 版本、渲染时长、注入 clip 数）。
- **产物事务**（`artifactTransaction.ts`）：产物要么整套落地，要么不落地。
- **PSNR 回归**（`regression-harness-psnr`）：在检查点用 ffmpeg `psnr` 跟参考渲染比，
  阈值判定；**旧实现留着当 oracle** 单测新实现。
- **capturePlan 是一个不可变值**，`replanAfterFailure` 是唯一的回退转移点
  （原来几个可变布尔会在回退期间组合出非法状态）；**captureCost** 先量这台机器的截图成本，
  再定 worker 数和路线。
- **确定性是可测的**：`vfxDeterminism.test.ts`、`runtime-conformance`、
  `htmlCompiler.parity.test.ts`（**编译路径之间的 parity** —— 我们恰好也有 HTML/SVG 两条路，
  而它们行为并不一致）、`freezePlan` + `planHash`。

### 5. 组织方式：把「手艺」写成 agent 能读的技能

他们不做一本大文档，而是**一个 gateway + 若干技术技能**：`motion-doctrine`（法则，先读）
→ 路由到 `cut-the-curve`（过渡全目录）、`seam-craft`（接缝的渲染前提）、
`captions-overlay`、`oversized-cursor`……每条 skill 的 frontmatter 写清
**什么时候加载**和**不覆盖什么**（「Does NOT contain the per-transition catalog」）。

我们相反：知识全压在**一个 AGENTS.md** 里（现在已超出工作区预算、加载时被截断），
而且**没有路由** —— 改字幕的人要读完整个文件才知道哪一节跟他有关。

## 视频动效：只做「讲内容」的动效

**被用户否掉过一次，别再犯**：第一版给每段画面加了缓慢推近/拉远 + 平移（Ken Burns），
理由是「一张静止画面撑久了像 PPT」。原话是「**这种图片无意义的放大、移动和缩小没有价值，
重点是突出解读的内容**」—— 那种运动跟正在讲的内容无关，观众一眼看得出它只是在动。

现在留下的三件事都跟内容直接相关：**「本段要点」强调行**（每段必有一句）、
**字幕逐句出现 + 句子里的阿拉伯数字标成强调色**、**顶部进度条**（是导航，不是装饰）。

**改这块之前先读 `docs/VIDEO_MOTION.md`**：转场为什么只能在片段内部做（不能跨片段
`xfade`）、字幕换句怎么对齐真实停顿、声波条怎么上色、进度条为什么不能用 `drawbox`，
以及四条实测踩出来的坑（`showwaves` 在某些宽度全黑、声波条必须画在字幕带之后、
resvg 按宽度缩放而不是拉伸、强调行长度中英文必须分开定）。那里是完整推导，这里只留结论。

**弹簧缓动**（参考做法里的原话是「用弹簧和缓动曲线，**不要线性运动**」）：三处已经换掉 ——
强调行滑入（原来是匀速 936px）、聚光灯位移（原曲线单调、无过冲）、逐句数字胶囊
（原来只有淡入）。公式与三种形态（Python / ffmpeg 表达式 / 页面 JS）只在
`services/motion.py` 写一遍，`tests/test_motion.py` 两两比数值。
**过冲量分开定**：滑入 2%（936px → 19px），胶囊 9%（30px → 2.7px）。
**改数字前先看 `docs/VIDEO_MOTION.md`**：峰值放早了会「啪」一下贴上去（0.08 秒走 96%）。
