# 成片自查与响度：**只有成片里才看得出来的那三件事**

分层测试能证明「字幕会换、动效会动」，但证明不了「整条片子里有 10 秒什么也没发生」——
那是**时间轴上的性质**，不是某一帧的性质。所以合成完输出之后，还要对**成片本身**量三样：

| 量什么 | 为什么它只能在成片上量 | 实现 |
|---|---|---|
| 画面有没有长时间不动 | 需要按时间轴抽样比对，单帧测试看不见 | `video_qa.find_static_gaps` |
| 响度够不够 | 归一化是在 ffmpeg 里做的，**写对滤镜串 ≠ 生效** | `loudness.measure_loudness`（量**成片**，不是源音频） |
| 音画长度差 | `-shortest` 的结果只有封装完才知道 | `video_qa.qa_video(audio_path=…)` |

结果存进 `video.qa`（跟着 `VideoResult.to_dict()` 一起进库），日志里同时打一行摘要 +
「最严重的 3 个问题」。命令行也能单独跑：

```bash
cd backend && ../.venv/bin/python -m app.services.video_qa ../data/videos/<id>.mp4 <音频路径>
```

## 静止空档：判据是标定出来的

做法：`ffmpeg -vf fps=2,scale=64x36:flags=area,format=gray -f rawvideo -` 把片子解成
一串 64×36 灰度帧，在 Python 里逐对比较（纯标准库，224 秒的片子约 1.7 秒）。

**「变了多少像素」的门槛**用真实成片 + 库里存的段起始时间标定过（字幕是按段换的，
所以段起点就是「该有新东西」的时刻）：

| 变化比例（灰阶差 >12 的像素占比） | 出现对数（100dce22，447 对） | 这是什么 |
|---|---|---|
| 恰好 0 | 197 | 真的一个像素都没变 |
| < 0.001 | 68 | 进度条在爬 |
| 0.001 ~ 0.003 | 56 | 进度条 + 声波条 + 淡入中间帧 |
| 0.003 ~ 0.006 | 24 | 噪声与信号混在一起的一档 |
| **≥ 0.006** | 102 | **字幕换句 / 强调行 / 换图**（其中 59% 落在段起点 ±0.75 秒内，随机基准 22%） |
| ≥ 0.02 | 65 | 整块换图、片尾卡这种画面级变化 |

门槛因此定在 **0.006**（`CHANGE_RATIO`）：放宽到 0.003 会让事件数从 102 涨到 126，
多出来的那批只有 40% 落在段起点附近 —— 就是噪声。

**按这条量出来的现状（三条真实成片）**：

| 集 | 落在「≥4 秒无可见变化」里的时长 | 最长的一段 |
|---|---|---|
| 100dce22 | 52.5% | 11.5 秒 |
| 666adf5b | 58.0% | 9.5 秒 |
| 4e594ee2.en | 67.7% | 11.0 秒 |

也就是说参考做法里那条「每 2–4 秒画面上要有新东西」的规矩，**我们目前是不达标的**。
空档本身不是 bug（一句 30 字的话本来就要念 10 秒），但它现在是一条**可量的指标** ——
先能量，才谈得上改不改、改哪里。报告给的是「最长的那 3 段 + 时间点」。
抽样时间点的精度是 `1/fps`（0.5 秒），别拿它当帧级证据。

## 响度：能到 -14 就到，到不了就守住 true peak

目标 `-14 LUFS / true peak ≤ -1.5 dBFS`（`loudness.TARGET_*`），在**封装那一步**
用两遍法的 `loudnorm` 做（`normalization_chain` 先量一遍、把 `measured_*` 填进第二遍）。
放在这一步是因为那是唯一处理音频的地方，不用多一次转码。

**实测现状（真实成片，用 `ffmpeg -af ebur128` 逐条量出来的）**：

| 集 | Integrated | True peak |
|---|---|---|
| 100dce22 | -15.7 LUFS | -0.8 dBFS |
| 4e594ee2 / 4e594ee2.en | -15.8 / -15.1 LUFS | -1.1 / -0.6 dBFS |
| 全库 18 个成片 | -15.1 ~ -15.8（横版 3f4c1923 是 -18.0） | -0.6 ~ -1.5 dBFS |

> 这张表 2026-10 修过一次：**原来那三行的数字（-18.1 / -18.4 / RMS -22.9）量的是源音频，
> 不是成片**。`qa_video(audio_path=…)` 把 `audio_path` 同时当成了「量长度的参照」和
> 「量响度的对象」，于是报告里写的 -18.1 而 MP4 实际是 -15.7 —— 差 2.4 LU，
> 方向还正好相反：数字看着「没抬起来」，其实抬起来了；万一哪天滤镜链静默失效，
> 报告也照样是这个数。现在 `audio_path` 只用于长度，响度一律量成片
> （`tests/test_video_qa.py::TestLoudness::test_qa_reports_the_shipped_file_not_the_source`）。

两件事值得记下来：

1. **同一套流水线出来的集，响度能差 4~5 LU**（源音频；归一化之后收在 0.7 LU 以内）——
   用户连着听两集要来回拧音量，这才是归一化真正要解决的问题。
2. **-14 LUFS 在一部分素材上「到不了」**：100dce22 要到 -14 得加 +4.14 dB，
   而它的 true peak 已经在 -1.4 dBFS —— 加完峰值 +2.7 dBFS，必然削波。
   **这是 ffmpeg 自己的结论**：两遍法的 JSON 里 `target_offset: 1.70`、
   `output_i: -15.70`（单遍 dynamic 也是同一个数 -15.7）。
   要真踩到 -14 只能上压缩（那 1% 最响的样本只比峰值低 1.2 dB，会被压得很勤），
   那是**会听得出来的音色改动**，不在「归一化」的范围里，需要单独决策。

所以策略是：**能到 -14 就到 -14，到不了就把 peak 守在 -1.5 dBFS 上停住**，
并把「差多少」记进报告（`below_target_lu` / `target_offset_lu`）。

**真实成片改造前后（同一集 f7c8af00，改完当场重新合成量的）**：

| | 改之前 | 改之后 |
|---|---|---|
| Integrated | -17.8 LUFS | **-15.5 LUFS**（+2.3 dB） |
| True peak | -1.5 dBFS | -1.0 dBFS |
| 静止空档占比 | 59.2% | 59.6% |

两句话要说清楚：**响度确实抬起来了**（+2.3 dB，离目标还差 1.5 LU）；
**空档指标当时没有变好** —— 那一轮做的是「让这类问题第一次变得可量」，
弹簧动效对「≥4 秒无变化」的计数几乎没有影响。

## 后来把空档压下去了：字幕按小句依次出现

空档的成因很具体：一句 30 字的话念 10 秒，**整句在第 0.35 秒就全出现了**，
中间那 10 秒画面上什么都不变。既然只有「句子出现」这一个事件，那就把它拆开 ——
按小句（逗号/顿号/分号/冒号处）依次显露，读到哪里字长到哪里。

做法：每个状态都是**同一张带子**（同一套排版，只把还没轮到的小句 `color: transparent`），
编码时按时间表依次叠上去。时间表由 `video_core.plan_reveals` 按小句字数占比算出来，
**渲染侧算一次、存进 `CaptionBand.reveals`，编码侧直接用**（不各算一遍）。

**实测（同一集 f7c8af00，上表那两列之后又合成了一次）**：

| | 只有整句出现 | 按小句出现 |
|---|---|---|
| 画面变化次数 | 97 | **132** |
| 最长静止 | 9.5 秒 | 9.0 秒 |
| **静止空档占比** | 59.6% | **21.2%** |

剩下的 10 段空档大多是 4~6.5 秒，**最长的那段（219.5→228.5 秒）是片尾品牌卡** ——
那一段本来就是静止的牌子（片尾不放声波条），这条空档是设计使然，不用去填。

几条踩过的坑写在 `docs/VIDEO_MOTION.md`「字幕按小句依次出现」一节：
状态的含义是「从第几个小句起藏起来」（差一位会让第一个状态和底图一模一样）、
最后一个状态必须「全都显示」（否则最后那一小句永远藏着）、
以及**这套只在 HTML 路径生效**（SVG 降级时退回整句出现）。
另外注意 true peak 落在了 **-1.0 dBFS**（比目标高 0.5 dB）：这是 loudnorm 动态模式的
已知行为（它优先保响度），远没有削波，但如果以后要严格守 -1.5，得在它后面再挂一个限幅器。

**静音不是「很轻的声音」**：ebur128 对数字静音报的是 `I: -70.0 LUFS`（它的下限），
拿它算增益会得到「+56 dB」这种荒唐结果。低于 `SILENCE_LUFS = -60` 一律当**测不到**，
调用方退回原行为（不假装测到了）。

## 端到端怎么验

`tests/test_video_qa.py` 里两条是核心，都不是「字符串里有这个字段」：

- `test_a_frozen_picture_is_detected`：真的编一段 6 秒不动的画面 → 空档必须被抓到；
  反过来 `test_changing_content_is_not_flagged`：每 1.5 秒换一次颜色 → 不许误报。
- `test_encoding_actually_raises_the_loudness`：造一段振幅 0.03 的音轨，
  出片**再量一遍**，响度必须被抬起来，且 true peak 不越线 ——
  这是唯一能证明「归一化真的进了 MP4」的断言。

## 接缝审计：从「有没有卡住」到「切得对不对」

`video_qa` 那三条判据里有两条是**下限**（有没有长时间不动、响度够不够），
它们回答不了用户报过的另一类问题：「画面一直在反复切换、和语音对不上、有抖动」。
那类问题的落点是**接缝**——切点两侧的动有没有对上。

判据来自 [HyperFrames](https://github.com/heygen-com/hyperframes)（Apache-2.0）的
`motion-doctrine` / `seam-craft`，他们那套影片法则把接缝写成了可验证的量：

> How Scene A exits determines how Scene B enters：同轴、同向、速度匹配、
> **两边都还在动的时候切**；「停下来再切」「从静止开始」都是死拍子；
> **叠化没有载体**（在他们的 anti-pattern 里排第一）。

`services/seam_audit.py` 是**只读的那一半**：一次把整片解成 10fps 的 48×27 灰度小帧
（一趟 ffmpeg），在每个切点前后各取 0.7 秒，分三段看：

| 段落 | 范围 | 回答什么 |
|---|---|---|
| 切点附近 | ±0.25s | 这一下**跳了几步**：一步=硬切，多步=渐变/叠化 |
| 退出侧 | −0.7 ~ −0.25s | 这个场景**自己**在不在动 |
| 进入侧 | +0.25 ~ +0.7s | 下一个场景**自己**在不在动 |

读数：`change_before/after`（场景自己的运动幅度）、`axis_before/after`（方向）、
`kind`（`hard_cut` / `dissolve` / `seamless` / `static`）、速度比，以及一份
按他们法则算的 `issues`。命令行：

```bash
cd backend && ../.venv/bin/python -m app.services.seam_audit ../data/videos/<id>.mp4 9.03,10.98,25.48
```

**成本**：304 秒的片子整趟解码 + 量 39 处切点 ≈ **2.0 秒**（一次 ffmpeg 解码，
不是每个切点起一次进程——HyperFrames 在 PSNR 那处踩过这个坑：每个检查点 spawn 一次
会**每次从第 0 帧重新解码**，复杂度随检查点数平方增长）。

**现在只量、不拦**：结果进 `video.qa.seams` 并在日志打一行摘要。
理由是我们目前是「静态卡 + 叠化」的讲解风格，而这套法则面向的是连续镜头语言的宣传片 ——
它会（如实地）在多数切点报「两侧都没在动」。先拿它把现状量清楚、在更多成片上标定，
再谈要不要拿它当闸门。

**第一条实测（存量三集，切点=段落边界）**：

| 集 | 切点数 | 退出时已静止 | 进入从静止开始 | 渐变/叠化 | 方向对不上 |
|---|---|---|---|---|---|
| e3083750 | 39 | 39 | 39 | 37 | 0 |
| 100dce22 | 31 | 31 | 31 | 13 | 0 |
| f7c8af00 | 29 | 29 | 29 | 27 | 0 |

两侧的运动幅度都在 **0.01~0.4 灰度级**（判「几乎没在动」的阈值是 1.0），
方向一处都对不上不了——因为**本来就没有可对的方向**。换句话说：
我们片子的接缝是「静止 → 静止 + 一次 0.35 秒叠化」，
而那 0.35 秒的叠化正是这套法则里最弱的一档（没有载体）。
这跟 `video_qa` 量到的「静止空档 51.7%~61.6%」是同一件事的两个粒度：
一个说「中间那几秒没动」，一个说「该动的时候（切点）也没动」。

标定与坑记在 `tests/test_seam_audit.py`：用**已知性质**的合成片（硬切 / 0.35s 叠化 /
同向平移 / 反向平移 / 平移切静止）钉住读数，三个坑都在那里：
方向不能用差分质心（平移物体有两条边、质心几乎不动）、
同分要取 |位移| 最小的（纯色画面每个位移残差都是 0）、
硬切与渐变的步数门槛要跟着「场景自己的运动幅度」走。
